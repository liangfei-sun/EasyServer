## 1. 认识网络配置页面

EasyServer 将所有网络相关功能集中在一个页面：「**网络配置**」（侧边栏入口，路由 `/network`）。

```
┌─────────────────────────────────────────────────────────────┐
│ 网络配置                                                        │
│ ┌─────────────────────────────────────────────────────────┐   │
│ │ 网络状态      [已连接]                                    │   │
│ │ 访问方式: Cloudflare Tunnel   域名: example.com           │   │
│ │ 隧道状态: 已连接              已发布服务: 8 个             │   │
│ └─────────────────────────────────────────────────────────┘   │
│ ┌─────────────────────────────────────────────────────────┐   │
│ │ 当前方式管理区（隧道状态 / 服务发布 / 反代配置…）          │   │
│ └─────────────────────────────────────────────────────────┘   │
│ ┌─────────────────────────────────────────────────────────┐   │
│ │ ▸ 高级选项（IPv6 直连 / 自由配置 / 切换访问方式）          │   │
│ └─────────────────────────────────────────────────────────┘   │
│ ┌─────────────────────────────────────────────────────────┐   │
│ │ 域名信息（主域名 / SSL 邮箱）                              │   │
│ └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**页面结构说明：**

| 区块 | 作用 | 出现条件 |
|------|------|---------|
| 网络状态 | 总览当前访问方式、域名、连接状态 | 始终显示 |
| 推荐方案 | 引导首次配置的用户选择接入方式 | 未配置网络时 |
| 当前方式管理区 | 管理隧道 / 反代 / IPv6 的具体功能 | 已配置时按方式显示 |
| 高级选项 | IPv6 直连、自由配置、切换访问方式 | 始终显示（默认折叠） |
| 域名信息 | 修改主域名与 SSL 邮箱 | 始终显示 |

## 2. 选择适合你的访问方式

系统提供四种访问方式，绝大多数用户推荐使用第一种：

| 访问方式 | 是否需要域名 | 是否需要开放端口 | 是否需要公网 IP | 推荐场景 |
|---------|:---:|:---:|:---:|---------|
| **Cloudflare Tunnel** ⭐ | 是（托管于 Cloudflare） | 否 | 否 | 绝大多数用户，无需备案、免端口 |
| 域名反代（Nginx） | 是 | 是（如 8443） | 是 | 域名未托管在 Cloudflare、愿意带端口号访问 |
| IPv6 直连 | 否 | 是 | 是（IPv6） | 无域名但有公网 IPv6，直接 IP 访问 |
| 自由配置 | 可选 | 视模块而定 | 视模块而定 | 高级用户，自行在应用商店安装配置 |

```
如何选择？
│
├─ 有域名？
│   ├─ 域名托管在 Cloudflare → ★ Cloudflare Tunnel（免端口、免备案）
│   └─ 域名托管在别处（阿里云/DNSPod…）
│       ├─ 愿意带端口访问（如 :8443）→ 域名反代
│       └─ 希望免端口访问 → 将域名 NS 迁到 Cloudflare 后用 Tunnel
│
├─ 无域名？
│   ├─ 有公网 IPv6 → IPv6 直连（http://[IPv6]:端口）
│   └─ 无公网 IP → 免费域名（如 .eu.org/.nip.io）+ Tunnel
│
└─ 喜欢自己折腾 → 自由配置
```

> **注意**：混合模式（域名反代 + Tunnel 同时启用）已从界面移除。原因是同一子域名无法同时存在 A 记录与 CNAME 记录（DNS 冲突），实际无法正常工作。旧版本遗留的混合配置会自动按 Tunnel 模式展示，建议切换为单一模式。

## 3. 方式一：Cloudflare Tunnel（推荐）

### 3.1 工作原理

服务器主动向 Cloudflare 建立**出站**隧道连接，用户访问 Cloudflare 标准 443 端口，Cloudflare 通过隧道将请求转发到本地服务。

```
用户浏览器                          Cloudflare 边缘网络            你的服务器（无开放端口）
     │                                   │                              │
     │  https://notes.example.com        │  出站隧道连接（长期保持）      │
     ├──────────────────────────────────►│◄─────────────────────────────┤
     │                                   │                              │
     │◄──────────────────────────────────┤                              │
     │            ← 隧道转发 ←            │                              │
```

**优势**：无需开放任何入站端口、不受运营商/云厂商端口封锁限制、自带 SSL 证书、访问无需输入端口号。

### 3.2 前提条件

1. 域名已托管到 Cloudflare（在 Cloudflare 添加站点并将域名的 NS 记录改为 Cloudflare 分配的服务器）
2. 准备一个 Cloudflare **API Token**，需包含权限：
   - `Account · Cloudflare Tunnel · Edit`
   - `Zone · DNS · Edit`

> Token 创建方法见 [7.2 创建 Cloudflare API Token](#72-创建-cloudflare-api-token)。

### 3.3 一键接入

1. 进入「**网络配置**」页面，若尚未配置会看到「推荐方案」卡片，点击 Cloudflare Tunnel 的 **「一键接入」**
2. 粘贴 API Token → 点击 **「验证 Token」**（系统会校验权限并显示账户/域名托管状态）
3. 点击 **「一键接入」**，系统自动完成：
   - 创建或复用同名隧道
   - 保存凭证并启动 cloudflare-tunnel 容器
   - 检查域名托管状态
4. 等待约 10~30 秒，页面显示「已连接」即接入成功

### 3.4 发布服务

接入完成后，在「服务发布」卡片的「可发布」页签中找到目标服务，点击 **「发布」**：

1. 自动添加隧道路由（hostname → http://localhost:端口）
2. **自动创建 DNS CNAME 记录**（子域名 → 隧道ID.cfargotunnel.com），无需登录 Cloudflare 手动添加
3. 发布后通过 `https://子域名.你的域名` 免端口访问

| 服务 | 发布后访问地址 |
|------|---------------|
| 管理面板 | `https://panel.你的域名` |
| NoteDiscovery | `https://notes.你的域名` |
| Uptime Kuma | `https://status.你的域名` |

**取消发布**：在「已发布」页签点击「取消发布」，系统同时删除路由与 DNS 记录。

### 3.5 重新接入

需要更换 API Token 或重新配置隧道时，在「隧道状态」卡片底部展开「重新接入」，粘贴新 Token 并确认即可。系统会复用已有隧道，不会影响已发布的路由。

## 4. 方式二：域名反代（Nginx）

### 4.1 工作原理

Nginx 在服务器上监听 HTTPS 端口（默认 8443），根据域名将请求转发给对应的本地服务。**需要域名解析到服务器公网 IP**。

```
用户浏览器                            你的服务器
     │                                    │
     │  https://notes.你的域名:8443       │
     ├───────────────────────────────────►│ Nginx (8443)
     │                                    ├──► NoteDiscovery (8000)
     │                                    ├──► Uptime Kuma (3001)
     │                                    └──► Jellyfin (8096)
```

### 4.2 前提条件

| 项目 | 说明 |
|------|------|
| 域名 | 任意 DNS 服务商托管（阿里云 / Cloudflare / DNSPod…） |
| 服务器公网 IP | 固定 IP 或使用 DDNS 动态域名 |
| 开放端口 | 服务器安全组/防火墙需放行 HTTPS 端口（如 8443） |
| DNS 解析 | 每个服务子域名解析到服务器 IP（可用系统自动同步，见下文） |

### 4.3 配置流程

1. 进入「**网络配置**」→ 点击「域名反代」方案的「展开配置」（或已配置时直接编辑「域名反代配置」卡片）
2. 选择 **DNS 提供商** 并填写凭证（用于自动创建解析记录与申请证书）
3. 设置 **HTTPS 端口**（默认 8443，详见[第 9 节](#9-端口说明)）与管理面板子域名
4. 点击 **「保存并应用」**，系统自动：
   - 保存 DNS 凭证
   - 生成 Nginx 反代配置并重载
5. 在「DNS 记录同步」区域点击 **「立即同步 DNS 记录」**，自动为所有子域名创建 A/AAAA 解析（详见[第 7 节](#7-dns-操作方法大全)）
6. 等待 DNS 生效（一般几分钟），即可通过 `https://子域名.你的域名:端口` 访问

### 4.4 已发布服务

Nginx 反代配置由系统自动生成：安装/卸载模块时自动增删对应 `server` 配置块，无需手动编辑。也可在页面点击「重新生成 Nginx 配置」手动触发。

## 5. 方式三：IPv6 直连

**直接用公网 IPv6 地址 + 端口访问服务**，无需域名、无需 DNS、无需 SSL 证书。

### 5.1 前提条件

- 服务器有公网 IPv6 地址（阿里云等云服务器需开通 IPv6 功能）
- 路由器/防火墙放行所需端口

### 5.2 查看 IPv6 地址

```bash
ip -6 addr show scope global
# 输出示例：inet6 2408:4001:xxxx:xxxx::1/64 scope global
```

### 5.3 启用方式

1. 进入「**网络配置**」→ 展开「**高级选项**」→ 点击「切换到 IPv6 直连」
2. 系统自动完成：
   - 停止 Nginx / ACME / Tunnel 等代理模块
   - 将服务监听地址 `BIND_ADDRESS` 切换为 `::`（监听所有 IPv6 接口）
   - 重启所有已安装模块以应用新绑定
3. 页面展示各服务的访问链接：`http://[IPv6地址]:端口`，点击即可复制

> **提示**：IPv6 直连无 HTTPS 加密，建议仅在内网或信任网络使用。切换到其他访问方式时，服务监听地址会自动恢复为仅本机（127.0.0.1），保证安全。

## 6. 方式四：自由配置

面向高级用户：**系统不自动管理任何网络模块**，由用户自行在「应用商店」安装和配置所需服务（Nginx、DDNS、ACME、Tunnel 等）。

启用方式：「**网络配置**」→「**高级选项**」→「切换到自由配置」。

自由配置模式下页面提供：
- 已安装网络模块的状态列表与启动/停止按钮
- 「前往应用商店」快捷入口
- 「重新生成 Nginx 配置」手动按钮

> 适用人群：熟悉 Docker 与网络配置的用户；普通用户建议使用 Tunnel 或域名反代模式，享受自动化管理。

## 7. DNS 操作方法大全

DNS 解析是域名反代模式的关键环节。EasyServer 提供**自动同步**（推荐）与**手动配置**两种方式。

### 7.1 自动同步（推荐）

在「网络配置 → 域名反代配置 → **DNS 记录同步**」区域，点击「立即同步 DNS 记录」，系统自动完成：

1. 检测服务器公网 IP（自动识别 IPv4 / IPv6）
2. 遍历所有已安装服务的子域名 + 管理面板子域名
3. 自动创建/更新解析记录：

| 检测到的公网 IP | 自动创建的记录 |
|----------------|---------------|
| 有 IPv4 | A 记录：子域名 → IPv4 地址 |
| 有 IPv6 | AAAA 记录：子域名 → IPv6 地址 |

**同步是幂等的**：
- 记录不存在 → 新建
- 记录值与当前 IP 一致 → 跳过（不重复请求）
- IP 已变化 → 自动更新（相当于 DDNS 动态解析）

**支持的 DNS 提供商**：

| 提供商 | 支持自动同步 | 凭证类型 |
|--------|:---:|---------|
| 阿里云 | ✅ | AccessKey ID + Secret |
| Cloudflare | ✅ | API Token（Zone:DNS:Edit 权限） |
| DNSPod / 华为云 / GoDaddy 等 | ❌（可用手动方式） | - |

**使用步骤（阿里云）**：
1. 网络配置 → 域名反代 → DNS 提供商选择「阿里云」
2. 填写 AccessKey（获取方法见 [7.3](#73-创建阿里云-accesskey)）
3. 保存后点击「立即同步 DNS 记录」，页面显示：`新建 X 条，更新 X 条，无变化 X 条`

**使用步骤（Cloudflare）**：
1. 网络配置 → 域名反代 → DNS 提供商选择「Cloudflare」
2. 填写 API Token（获取方法见 [7.2](#72-创建-cloudflare-api-token)）
3. 保存后点击「立即同步 DNS 记录」

> **注意（Cloudflare）**：域名反代创建的 A/AAAA 记录为「DNS only（灰色云朵）」模式，流量直连服务器 IP，不经过 Cloudflare 代理，避免与证书申请和端口访问冲突。

### 7.2 创建 Cloudflare API Token

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/profile/api-tokens) → My Profile → API Tokens
2. 点击 **Create Token**
3. 推荐选择模板 **Edit zone DNS**（自带 Zone:DNS:Edit 权限），或自定义 Token 添加：
   - `Account · Cloudflare Tunnel · Edit`（仅 Tunnel 模式需要）
   - `Zone · DNS · Edit`
4. 选择授权范围（Zone Resources → Include → 你的域名）
5. 生成后**立即复制保存**（仅显示一次）

```
生成的 Token 形如：cfut_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

> **重要**：以 `eyJ` 开头的长字符串是 **Tunnel Token**（cloudflared 运行时凭证），**不是** API Token，请勿混淆。两者区别见 [10.2](#102-提示-token-无效或-invalid-request-headers)。

### 7.3 创建阿里云 AccessKey

1. 登录 [阿里云 RAM 控制台](https://ram.console.aliyun.com/users) → 创建用户
2. 授权：`AliyunDNSFullAccess`（DNS 解析管理权限，可额外加 `AliyunDDNSFullAccess`）
3. 为该用户创建 AccessKey，复制 **AccessKey ID** 与 **AccessKey Secret**
4. 在 EasyServer 网络配置中填写这两项

### 7.4 手动配置 DNS（不使用自动同步）

**阿里云控制台**：

1. 登录 [阿里云云解析 DNS](https://dns.console.aliyun.com/)
2. 添加域名 → 进入解析设置 → 添加记录：

| 记录类型 | 主机记录 | 记录值 | 说明 |
|---------|:---:|---------|------|
| A | @ | 服务器公网 IPv4 | 主域名解析 |
| A | * | 服务器公网 IPv4 | 泛解析（推荐，所有子域名自动生效） |
| AAAA | * | 服务器 IPv6 | IPv6 泛解析（可选） |

**Cloudflare Dashboard**：

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/) → 选择域名 → DNS → Records
2. 点击 **Add record**：

| 类型 | 名称 | 内容 | 代理状态 |
|------|:---:|---------|---------|
| A | * | 服务器 IPv4 | DNS only（灰云） |
| AAAA | * | 服务器 IPv6 | DNS only（灰云） |

> **提示**：泛解析（`*`）可一次性覆盖所有子域名，新安装的服务无需再手动添加记录。若担心泛解析冲突，也可为每个服务单独添加记录。

**DNS 生效时间**：TTL 通常为 600 秒（10 分钟），修改后可通过以下命令验证：

```bash
# 验证解析是否生效（本机）
dig notes.example.com
# 或使用在线工具 https://dnschecker.org 查询全球生效状态
```

## 8. SSL 证书说明

### 8.1 证书来源

| 访问方式 | 证书来源 | 说明 |
|---------|---------|------|
| Cloudflare Tunnel | Cloudflare 边缘自动签发 | 无需任何配置 |
| 域名反代 | Let's Encrypt（ACME 模块自动申请） | 需 DNS 凭证用于验证 |
| IPv6 直连 | 无 | 直接 HTTP 访问 |

### 8.2 域名反代证书自动申请

在域名反代配置中填写 DNS 凭证后，ACME 模块会自动：

1. 通过 DNS API 添加 TXT 验证记录（自动删除）
2. 申请 Let's Encrypt 证书
3. 证书到期前 60 天自动续签

证书状态可在「域名反代配置 → SSL 证书」查看（有效/到期时间）。

**申请失败排查**：见 [10.6](#106-ssl-证书申请失败)。

## 9. 端口说明

### 9.1 HTTPS 端口选择

| 端口 | 适用场景 | 说明 |
|------|---------|------|
| 443 | 有公网 IPv4 且运营商未封锁 | 标准 HTTPS 端口，访问无需输入端口号 |
| **8443（默认）** | 国内家庭宽带/云服务器 | 运营商普遍不封锁，兼容性好 |
| 8442 / 9443 | 8443 被占用时 | 自定义高位端口 |

### 9.2 修改端口后的注意事项

1. 修改端口后系统自动重启 Nginx 容器（**必须重启才能绑定新端口**）
2. 检查云服务器安全组/防火墙是否放行新端口
3. 检查路由器端口转发规则是否同步更新
4. 域名反代模式下访问需带端口号：`https://status.你的域名:8443`

### 9.3 常用服务端口参考

| 服务 | 端口 |
|------|:---:|
| 管理面板 | 8900 |
| NoteDiscovery | 8000 |
| Uptime Kuma | 3001 |
| Jellyfin | 8096 |
| Calibre-Web | 8083 |
| FileBrowser | 8081 |
| Joplin | 22300 |
| Frigate | 5000 |

## 10. 常见问题排查（FAQ）

### 10.1 同步 DNS 提示「存在冲突的 CNAME 记录」

**现象**：域名反代模式下同步 DNS 记录失败，提示 *存在冲突的 CNAME 记录（xxx.cfargotunnel.com）*。

**原因**：该子域名此前通过 Cloudflare Tunnel 发布过，已有 CNAME 记录指向隧道。同一域名无法同时存在 CNAME 与 A 记录。

**解决**：
1. 在「网络配置 → 服务发布 → 已发布」中取消发布该服务
2. 重新点击「立即同步 DNS 记录」

### 10.2 提示 Token 无效或 Invalid request headers

**现象**：粘贴 Token 后验证失败，或自动同步报 *Invalid request headers*。

**原因**：混淆了两种 Token：

| Token 类型 | 开头 | 用途 |
|-----------|------|------|
| API Token | `cfut_` 或 40 位十六进制 | 调用 Cloudflare API（验证、DNS、隧道管理） |
| Tunnel Token | `eyJ…` | cloudflared 容器运行时凭证 |

**解决**：在 [API Tokens 页面](https://dash.cloudflare.com/profile/api-tokens) 重新创建 **API Token**（见 [7.2](#72-创建-cloudflare-api-token)），粘贴到网络配置中。

### 10.3 域名已添加解析但仍无法访问

按顺序排查：

1. **DNS 未生效**：泛解析记录修改后最长 10 分钟生效，用 `dig` 验证（见 [7.4](#74-手动配置-dns不使用自动同步)）
2. **端口未放行**：检查云服务器安全组 + 系统防火墙 + 路由器转发
3. **服务未运行**：到「服务管理」确认目标服务状态为「运行中」
4. **访问地址错误**：域名反代模式需带端口号（`:8443`）；Tunnel 模式无需端口
5. **本地网络缓存**：手机流量访问试试（排除本地 DNS 缓存）

### 10.4 修改域名后服务无法访问

**说明**：修改主域名**不会自动更新**已有配置（设计如此，避免误操作影响线上服务）。修改域名后需手动处理：

1. **Tunnel 模式**：所有已发布路由的域名已变化 → 需要「取消发布」后重新「发布」
2. **域名反代模式**：点击「重新生成 Nginx 配置」，并重新执行「DNS 记录同步」
3. **SSL 证书**：新域名需要重新签发证书（ACME 自动检测）

修改域名前系统会弹出确认提示，请仔细阅读影响范围。

### 10.5 IPv6 直连后服务仍然无法访问

1. **确认服务器有公网 IPv6**：`ip -6 addr show scope global`，无输出则未开通 IPv6
2. **确认 BIND_ADDRESS 已切换**：IPv6 直连模式下系统自动将监听地址设为 `::`；若此前手动改过 `.env` 可能未生效，重新切换一次模式
3. **防火墙放行**：`firewall-cmd --list-ports` 或安全组检查
4. **使用方括号访问**：URL 格式为 `http://[2408:xxxx::1]:端口`，IPv6 地址必须加方括号

### 10.6 SSL 证书申请失败

1. **DNS 凭证错误**：确认 AccessKey/Token 有 DNS 写入权限（阿里云需 `AliyunDNSFullAccess`）
2. **域名未解析**：证书验证依赖 DNS，先完成解析配置
3. **凭证混淆**：确认填的是 API Token 而非 Tunnel Token（见 [10.2](#102-提示-token-无效或-invalid-request-headers)）
4. **申请频率限制**：Let's Encrypt 每周每域名限 5 次，失败后等待 24 小时重试
5. **查看日志**：到「服务管理 → ACME → 日志」查看详细错误

### 10.7 无法检测到服务器公网 IP

**现象**：DNS 同步时提示 *无法检测到服务器公网 IP*。

**排查**：
1. 服务器网络是否正常（`ping 223.5.5.5`）
2. 是否可访问外网探测接口（`curl https://api.ipify.org`）
3. 某些专有网络环境需配置代理后重试

### 10.8 443 端口被运营商/云厂商封锁

国内云服务器未备案时通常封锁 443/80 端口，可选方案：

1. **使用 Cloudflare Tunnel**（推荐）：完全不依赖端口，访问无需带端口号
2. **改用 8443 等高位端口**：访问时带端口号
3. **IPv6 直连**：部分环境 IPv6 的 443 可用

## 11. 术语表

| 术语 | 说明 |
|------|------|
| API Token | Cloudflare 用于调用 API 的凭证，`cfut_` 开头，可配置权限 |
| Tunnel Token | cloudflared 运行时的隧道凭证，`eyJ` 开头，自动生成 |
| A 记录 | 域名 → IPv4 地址的解析记录 |
| AAAA 记录 | 域名 → IPv6 地址的解析记录 |
| CNAME 记录 | 域名 → 其他域名的别名记录 |
| 泛解析（*） | 匹配所有子域名的通配记录 |
| proxied / 代理 | Cloudflare 橙色云朵：流量经过 CF 网络；灰云 = DNS only 直连 |
| ingress 路由 | Tunnel 中"公网域名 → 本地服务"的映射规则 |
| DDNS | 动态 DNS，IP 变化时自动更新解析记录 |
