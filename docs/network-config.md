## 1. 功能概述

「网络配置」（侧边栏入口，路由 `/network`）是 EasyServer 所有网络功能的统一入口。在这里你可以完成：

- **选择访问方式**：Cloudflare Tunnel、域名反代、智能混合路由、IPv6 直连、自由配置，五种方式一键切换
- **域名与 DNS 管理**：配置域名、自动同步 DNS 解析记录，无需登录 DNS 服务商网站
- **服务发布**：把本地服务以子域名形式发布到公网，自动生成路由与解析
- **SSL 证书**：自动申请、自动续签 HTTPS 证书
- **按服务选择路由方式**（智能混合路由）：大带宽服务走域名反代，轻量服务走 Tunnel 中转

页面从上到下依次为：网络状态总览 → 当前模式的管理区 → Tunnel 中转服务卡片 → 高级选项（折叠） → 域名信息。整页全貌如下：

![网络配置页总览](images/network-config-overview.png)

| 区块 | 作用 | 出现条件 |
|------|------|---------|
| 网络状态 | 总览当前访问方式、域名、隧道连接状态 | 始终显示 |
| 推荐方案 | 引导首次配置的用户选择接入方式 | 未配置网络时 |
| 域名反代配置 | DNS 提供商与凭证、HTTPS 端口、SSL 证书、DNS 记录同步 | 域名反代 / 智能混合路由模式 |
| Tunnel 中转服务 | 按服务查看与切换路由方式、智能推荐一键配置 | 域名反代 / 智能混合路由模式 |
| 隧道状态 / 服务发布 | Tunnel 连接信息、服务的发布与取消发布 | Cloudflare Tunnel 模式 |
| 高级选项 | IPv6 直连、自由配置、切换访问方式 | 始终显示（默认折叠） |
| 域名信息 | 修改主域名与 SSL 邮箱 | 始终显示 |

## 2. 五种访问方式与选择建议

### 2.1 五种方式对比

| 访问方式 | 前提条件 | 适用场景 | 优点 | 缺点 |
|---------|---------|---------|------|------|
| **域名反代**（domain） | 域名（任意 DNS 服务商）+ 服务器公网可达（IPv4 或 IPv6）+ 放行 HTTPS 端口 | 域名未托管在 Cloudflare、有大带宽需求 | 带宽不经中转直达服务器、自动 SSL 证书、DNS 自动同步 | 访问需带端口号（如 `:8443`），需开放端口 |
| **Cloudflare Tunnel** ⭐ | 域名托管在 Cloudflare + Cloudflare API Token | 无公网 IP、443/80 端口被封、追求免端口 | 免公网 IP、免开端口、免备案、访问不带端口号 | 流量经 Cloudflare 中转，大带宽场景延迟与速度受影响 |
| **IPv6 直连**（ipv6_direct） | 服务器有公网 IPv6 | 无域名、内网或信任网络使用 | 无需域名、无需 DNS、无需证书，配置最简单 | 无 HTTPS 加密，访问方也需有 IPv6 网络 |
| **智能混合路由**（hybrid） | 域名 + DNS 凭证 + Cloudflare 账号（Tunnel 接入） | 同时拥有大带宽服务与轻量服务 | 按服务分流：大带宽走域名反代、轻量走 Tunnel 中转，两者优点兼得 | 需同时维护两套接入凭证，首次配置步骤稍多 |
| **自由配置**（custom） | 无 | 高级用户自行折腾 | 系统不干预，完全自主 | 无自动化管理，需自行配置 |

### 2.2 如何选择？

按下面的顺序问自己几个问题即可：

1. **服务器有公网 IPv6 且带宽较大**（家庭宽带、视频流、云盘场景）→ 选「域名反代」；如果还有一些轻量服务想免端口访问 → 选「智能混合路由」
2. **没有公网 IP，或云服务器 443/80 端口被封**（未备案）→ 选「Cloudflare Tunnel」，把域名托管到 Cloudflare 即可
3. **既有大带宽媒体服务（Jellyfin / Frigate / Nextcloud），又有轻量服务（笔记、监控面板）** → 选「智能混合路由」，系统会帮你按服务分流
4. **没有域名，但服务器有公网 IPv6** → 选「IPv6 直连」
5. **熟悉 Docker 与网络配置，想完全自己控制** → 选「自由配置」

> 绝大多数普通用户推荐：**Cloudflare Tunnel**（最省心）或 **智能混合路由**（体验与带宽兼得）。

## 3. 智能混合路由使用指南（新功能）

### 3.1 概念：两种路由方式按服务并存

智能混合路由让「域名反代」与「Tunnel 中转」**同时生效**，你可以为每个服务单独选择走哪条路：

| 路由方式 | 流量路径 | 访问地址格式 | 适合 |
|---------|---------|-------------|------|
| **域名反代** | DNS AAAA → 服务器 IPv6 → Nginx SSL → 服务 | `https://子域名.你的域名:HTTPS端口`（即您配置的 HTTPS 端口，默认 8443） | 视频流、云盘等大带宽服务 |
| **Tunnel 中转** | DNS CNAME → Cloudflare 边缘 → Tunnel → 服务 | `https://子域名.你的域名`（免端口） | 笔记、面板等轻量服务 |

同一个子域名在同一时刻只会走其中一条路：切换路由方式时，系统会自动维护对应的 DNS 记录（域名反代 = A/AAAA 记录，Tunnel 中转 = CNAME 记录），你无需手动操作 DNS。

### 3.2 配置步骤

**第 1 步：完成前置配置**

- 已在「域名信息」中填写主域名
- 已在「域名反代配置」中配置 DNS 提供商与凭证（用于 DNS 自动同步与 SSL 证书，见[第 4 节](#4-域名反代模式配置要点)）
- 已接入 Cloudflare Tunnel（若尚未接入，「Tunnel 中转服务」卡片内会有「接入 Cloudflare Tunnel」引导按钮，点击后按弹窗指引粘贴 API Token 即可，见 [5.2 节](#52-cloudflare-tunnel-模式)）

**第 2 步：切换访问方式为「智能混合路由」**

1. 打开「网络配置」→ 展开底部「**高级选项**」→ 找到「切换访问方式」区域（见下图，三个按钮分别是 Cloudflare Tunnel / 域名反代 / 智能混合路由）

![切换访问方式区域](images/mode-selector.png)

2. 点击「**智能混合路由**」按钮，在确认弹窗中点击「确认切换」
3. 页面出现全屏加载提示「正在切换访问方式，首次切换需安装并启动相关模块，可能需要几分钟，请勿关闭页面」——**这是正常现象**：首次切换会自动安装并启动 Nginx、ACME、DDNS、Cloudflare Tunnel 等模块，耗时可能达到几分钟
4. 看到提示「已切换到 智能混合路由」、页面顶部出现蓝色说明条（智能混合路由：域名反代 + Tunnel 中转并存）即表示切换成功

**第 3 步：为每个服务选择路由方式**

在「**Tunnel 中转服务**」卡片中，每个已安装的服务都列在表格里：

![Tunnel 中转服务卡片](images/tunnel-services-card.png)

- 「路由方式」列的标签显示当前走法：蓝色 `Tunnel 中转` 或绿色 `域名反代`
- 「访问地址」列直接给出可用的完整地址：Tunnel 中转的服务免端口，域名反代的服务带您配置的 HTTPS 端口（默认 8443）
- 想让某个服务换条路，点右侧的「**切换为 Tunnel 中转**」或「**切换为 域名反代**」按钮，看到提示「xxx 已切换为 Tunnel 中转 / 域名反代」、表格标签同步变化即为成功。切换后系统自动更新 DNS 记录，一般几分钟内生效

**第 4 步（可选）：「智能推荐」一键配置**

不想逐个挑选？点击卡片右上角的「**智能推荐**」按钮，确认弹窗后系统按以下策略一键调整：

| 分组 | 服务 | 路由方式 |
|------|------|---------|
| 大带宽服务 | Frigate、Nextcloud、Jellyfin、FileBrowser、Calibre-Web | 域名反代 |
| 轻量服务 | NoteDiscovery、Joplin、Uptime Kuma | Tunnel 中转 |
| 其他服务 | — | 保持当前方式不变 |

完成后提示「智能配置完成：大带宽服务走域名反代，轻量服务走 Tunnel 中转」。

### 3.3 DNS 自动行为说明

切换路由方式时，系统在后台自动维护 DNS 记录，无需手动操作：

- 服务切换为 **Tunnel 中转** → 自动创建 CNAME 记录指向隧道（若该子域名原有 A/AAAA 记录会先清理，避免冲突）
- 服务切换回 **域名反代** → 自动删除对应 CNAME，由「立即同步 DNS 记录」补建 A/AAAA 记录
- 切换为智能混合路由模式时，系统会自动执行一次 DNS 同步（后台进行，不阻塞页面）

在「DNS 记录同步」的结果中可能会看到「**跳过 N 条**」：这表示对应子域名已存在 CNAME 记录（该服务已通过 Tunnel 中转发布），系统为避免冲突而主动跳过，**属于正常的冲突保护机制，不是错误**。

## 4. 域名反代模式配置要点

### 4.1 工作原理

Nginx 在服务器上监听 HTTPS 端口（默认 8443），根据域名将请求转发给对应的本地服务。**需要域名解析到服务器公网 IP**。

```
用户浏览器                            你的服务器
     │                                    │
     │  https://notes.你的域名:8443       │
     ├───────────────────────────────────►│ Nginx (8443)
     │                                    ├──► NoteDiscovery (8000)
     │                                    ├──► Uptime Kuma (3001)
     │                                    └──► Jellyfin (8096)
```

### 4.2 前提条件

| 项目 | 说明 |
|------|------|
| 域名 | 任意 DNS 服务商托管（阿里云 / Cloudflare / DNSPod…） |
| 服务器公网 IP | 固定 IP 或使用 DDNS 动态域名 |
| 开放端口 | 服务器安全组/防火墙需放行 HTTPS 端口（默认 8443，可修改） |
| DNS 解析 | 每个服务子域名解析到服务器 IP（可用系统自动同步，见下文） |

### 4.3 配置流程

1. 进入「**网络配置**」→ 点击「域名反代」方案的「展开配置」（首次配置），或直接编辑「域名反代配置」卡片（已配置时）
2. 选择 **DNS 提供商** 并填写凭证（用于自动创建解析记录与申请证书）
3. 设置 **HTTPS 端口**（默认 8443，详见[附录 B](#附录-bssl-证书与端口说明)）与管理面板子域名
4. 点击 **「保存并应用」**，系统自动保存 DNS 凭证、生成 Nginx 反代配置并重载
5. 在「DNS 记录同步」区域点击 **「立即同步 DNS 记录」**，自动为所有子域名创建 A/AAAA 解析
6. 等待 DNS 生效（一般几分钟），页面出现 `同步完成：新建 X 条，更新 X 条…` 提示后，即可通过 `https://子域名.你的域名:端口` 访问

### 4.4 DNS 自动同步

点击「立即同步 DNS 记录」后系统自动完成：检测服务器公网 IP（自动识别 IPv4/IPv6）→ 遍历所有服务子域名 → 创建或更新解析记录。

**同步是幂等的**：记录不存在则新建；记录值与当前 IP 一致则跳过；IP 已变化则自动更新（相当于 DDNS 动态解析）。

| 提供商 | 支持自动同步 | 凭证类型 |
|--------|:---:|---------|
| 阿里云 | ✅ | AccessKey ID + Secret |
| Cloudflare | ✅ | API Token（Zone:DNS:Edit 权限） |
| DNSPod / 华为云 / GoDaddy 等 | ❌（可用手动方式，见[附录 A](#附录-adns-凭证创建与手动配置)） | - |

> **注意（Cloudflare）**：域名反代创建的 A/AAAA 记录为「DNS only（灰色云朵）」模式，流量直接到达服务器 IP，不经过 Cloudflare 代理，避免与证书申请和端口访问冲突。

### 4.5 SSL 证书自动申请

填写 DNS 凭证后，ACME 模块自动通过 DNS API 验证域名、申请 Let's Encrypt 证书，并在到期前 60 天自动续签。证书状态可在「域名反代配置 → SSL 证书」查看（有效/到期时间）。申请失败排查见 [6.8 节](#68-ssl-证书申请失败)。

### 4.6 Nginx 配置自动维护

Nginx 反代配置由系统自动生成：安装/卸载模块时自动增删对应配置块，无需手动编辑。也可在页面点击「重新生成 Nginx 配置」手动触发。

## 5. 其他模式配置要点

### 5.1 IPv6 直连

**直接用公网 IPv6 地址 + 端口访问服务**，无需域名、无需 DNS、无需 SSL 证书。

前提：服务器有公网 IPv6 地址（阿里云等云服务器需开通 IPv6），防火墙放行所需端口。

启用步骤：

1. 「网络配置」→「高级选项」→ 点击「**切换到 IPv6 直连**」
2. 系统自动停止 Nginx / ACME / Tunnel 等代理模块，将服务监听地址切换为所有接口（含 IPv6），并重启已安装模块
3. 页面展示各服务的访问链接 `http://[IPv6地址]:端口`，点击即可复制

> **提示**：IPv6 直连无 HTTPS 加密，建议仅在内网或信任网络使用。切换到其他方式时，监听地址会自动恢复为仅本机，保证安全。

### 5.2 Cloudflare Tunnel 模式

**工作原理**：服务器主动向 Cloudflare 建立**出站**隧道连接，用户访问 Cloudflare 标准 443 端口，请求经隧道转发到本地服务。无需开放任何入站端口、不受端口封锁限制、自带 SSL、访问免端口号。

**前提条件**：

1. 域名已托管到 Cloudflare（在 Cloudflare 添加站点并将域名的 NS 记录改为 Cloudflare 分配的服务器）
2. 准备一个 Cloudflare **API Token**，需包含权限：`Account · Cloudflare Tunnel · Edit` + `Zone · DNS · Edit`（创建方法见[附录 A](#附录-adns-凭证创建与手动配置)）

**一键接入**：

1. 进入「网络配置」，未配置时点击 Cloudflare Tunnel 卡片的 **「一键接入」**（已配置的用户可在「Tunnel 中转服务」卡片点击「接入 Cloudflare Tunnel」）
2. 按弹窗提示粘贴 API Token → 点击 **「验证 Token」**，看到「Token 有效」即通过
3. 点击 **「一键接入」**，弹窗中逐步显示日志：创建/复用隧道 → 启动 cloudflare-tunnel 容器 → 检查域名托管状态
4. 看到「接入完成！」绿色提示，且「网络状态」中隧道状态显示「已连接」，即接入成功

**发布服务**：在「服务发布」卡片的「可发布」页签中找到目标服务，点击 **「发布」**：

1. 自动添加隧道路由（子域名 → 本地服务端口）
2. **自动创建 DNS CNAME 记录**，无需登录 Cloudflare 手动添加
3. 发布后通过 `https://子域名.你的域名` 免端口访问；在「已发布」页签点击「取消发布」可同时删除路由与 DNS 记录

**重新接入**：需要更换 API Token 时，在「隧道状态」卡片底部展开「重新接入」，粘贴新 Token 并确认即可，系统会复用已有隧道，不影响已发布的路由。

### 5.3 自由配置

面向高级用户：**系统不自动管理任何网络模块**，由你自行在「应用商店」安装和配置所需服务（Nginx、DDNS、ACME、Tunnel 等）。

启用方式：「网络配置」→「高级选项」→「切换到自由配置」。该模式下页面提供已安装网络模块的状态列表与启动/停止按钮、「前往应用商店」快捷入口和「重新生成 Nginx 配置」手动按钮。

> 普通用户建议使用 Tunnel、域名反代或智能混合路由模式，享受自动化管理。

## 6. 常见问题 FAQ

### 6.1 切换访问方式时页面一直转圈，是不是卡死了？

**正常现象**。首次切换到某种方式时，系统会自动安装并启动相关模块（如 Nginx、ACME、DDNS、Cloudflare Tunnel），页面会显示「正在切换访问方式，首次切换需安装并启动相关模块，可能需要几分钟」的全屏提示。整个过程可能持续数分钟，**请勿关闭或刷新页面**，等待提示「已切换到 xxx」即为成功。

### 6.2 为什么有的服务访问地址免端口，有的带端口号？

取决于该服务的路由方式：

- **Tunnel 中转**的服务：`https://子域名.域名`，流量经 Cloudflare 标准 443 端口中转，**免端口**
- **域名反代**的服务：`https://子域名.域名:HTTPS端口`，端口为您在「域名反代配置」中设置的 HTTPS 端口（默认 8443），**必须带端口**

「Tunnel 中转服务」卡片的「访问地址」列会自动给出正确格式，直接复制使用即可，无需自己拼。

### 6.3 DNS 同步结果出现「跳过」怎么办？

**无需处理**。「跳过」表示该子域名已存在 CNAME 记录（对应服务已通过 Tunnel 中转发布），同一子域名无法同时存在 CNAME 与 A/AAAA 记录，系统主动跳过以保护 Tunnel 路由，属于正常的冲突保护机制。若你确实想让该服务改回域名反代，请先在「Tunnel 中转服务」卡片将其「切换为域名反代」，再重新点击「立即同步 DNS 记录」。

### 6.4 从 Tunnel 中转移切回域名反代后，服务短暂无法访问？

**属于 DNS 生效延迟**。切换路由方式后，DNS 记录的变更需要时间在全球生效（通常几分钟，最长约 10 分钟）。处理建议：

1. 等待几分钟后再访问
2. 可手动点击「**立即同步 DNS 记录**」，确认该子域名的 A/AAAA 记录已补建（同步结果中不应再出现「跳过」）
3. 仍不行时，用手机的移动网络访问试试（排除本地 DNS 缓存），或在浏览器无痕窗口打开

### 6.5 「Tunnel 中转服务」卡片显示「尚未接入 Cloudflare Tunnel」？

这说明你当前是域名反代模式且还没有接入 Tunnel，所有服务都通过域名反代访问。如果希望使用混合路由：

1. 点击卡片中的「**接入 Cloudflare Tunnel**」按钮
2. 前提：域名已托管在 Cloudflare，并已创建 API Token（见[附录 A](#附录-adns-凭证创建与手动配置)）
3. 按弹窗提示粘贴 Token → 验证 → 一键接入，完成后卡片即显示服务路由列表

如果你不需要 Tunnel，忽略该卡片即可，不影响域名反代的正常使用。

### 6.6 同步 DNS 提示「存在冲突的 CNAME 记录」

**原因**：该子域名此前通过 Tunnel 发布过，已有 CNAME 指向隧道，同一域名无法同时存在 CNAME 与 A 记录。

**解决**：在「Tunnel 中转服务」或「服务发布 → 已发布」中将对应服务切换回域名反代（取消发布），然后重新点击「立即同步 DNS 记录」。

### 6.7 提示 Token 无效或 Invalid request headers

**原因**：混淆了两种 Cloudflare Token：

| Token 类型 | 开头 | 用途 |
|-----------|------|------|
| API Token | `cfut_` 或 40 位十六进制 | 调用 Cloudflare API（验证、DNS、隧道管理） |
| Tunnel Token | `eyJ…` | cloudflared 容器运行时凭证 |

**解决**：在 [API Tokens 页面](https://dash.cloudflare.com/profile/api-tokens) 重新创建 **API Token**（见[附录 A](#附录-adns-凭证创建与手动配置)），粘贴到网络配置中。

### 6.8 SSL 证书申请失败

1. **DNS 凭证错误**：确认 AccessKey/Token 有 DNS 写入权限（阿里云需 `AliyunDNSFullAccess`）
2. **域名未解析**：证书验证依赖 DNS，先完成解析配置
3. **凭证混淆**：确认填的是 API Token 而非 Tunnel Token（见 [6.7](#67-提示-token-无效或-invalid-request-headers)）
4. **申请频率限制**：Let's Encrypt 每周每域名限 5 次，失败后等待 24 小时重试
5. **查看日志**：到「服务管理 → ACME → 日志」查看详细错误

### 6.9 域名已添加解析但仍无法访问

按顺序排查：

1. **DNS 未生效**：解析修改后最长 10 分钟生效，用 `dig 子域名.你的域名` 验证
2. **端口未放行**：检查云服务器安全组 + 系统防火墙 + 路由器转发，需放行 HTTPS 端口
3. **服务未运行**：到「服务管理」确认目标服务状态为「运行中」
4. **访问地址错误**：域名反代需带端口号（您配置的 HTTPS 端口，默认 8443）；Tunnel 中转无需端口
5. **本地网络缓存**：换手机流量访问试试（排除本地 DNS 缓存）

### 6.10 修改域名后服务无法访问

修改主域名**不会自动更新**已有配置（设计如此，避免误操作影响线上服务）。修改后需手动处理：

1. **Tunnel 已发布路由**：需「取消发布」后重新「发布」
2. **域名反代**：点击「重新生成 Nginx 配置」，并重新执行「立即同步 DNS 记录」
3. **SSL 证书**：新域名需要重新签发（ACME 自动检测）

### 6.11 443 端口被运营商/云厂商封锁

国内云服务器未备案时通常封锁 443/80 端口，可选方案：

1. **Cloudflare Tunnel**（推荐）：完全不依赖入站端口，访问免端口号
2. **域名反代改用高位端口**（默认 8443）：访问时带端口号
3. **智能混合路由**：轻量服务走 Tunnel 中转免端口，大带宽服务走域名反代带端口

## 附录 A：DNS 凭证创建与手动配置

### A.1 创建 Cloudflare API Token

1. 登录 [Cloudflare Dashboard](https://dash.cloudflare.com/profile/api-tokens) → My Profile → API Tokens
2. 点击 **Create Token**
3. 推荐选择模板 **Edit zone DNS**（自带 Zone:DNS:Edit 权限），或自定义 Token 添加：
   - `Account · Cloudflare Tunnel · Edit`（Tunnel 接入 / 智能混合路由需要）
   - `Zone · DNS · Edit`
4. 选择授权范围（Zone Resources → Include → 你的域名）
5. 生成后**立即复制保存**（仅显示一次）

> **重要**：以 `eyJ` 开头的长字符串是 **Tunnel Token**（cloudflared 运行时凭证），**不是** API Token，请勿混淆。

### A.2 创建阿里云 AccessKey

1. 登录 [阿里云 RAM 控制台](https://ram.console.aliyun.com/users) → 创建用户
2. 授权：`AliyunDNSFullAccess`（DNS 解析管理权限，可额外加 `AliyunDDNSFullAccess`）
3. 为该用户创建 AccessKey，复制 **AccessKey ID** 与 **AccessKey Secret**
4. 在 EasyServer 网络配置中填写这两项

### A.3 手动配置 DNS（不使用自动同步）

**阿里云控制台**：登录 [阿里云云解析 DNS](https://dns.console.aliyun.com/) → 添加域名 → 解析设置 → 添加记录：

| 记录类型 | 主机记录 | 记录值 | 说明 |
|---------|:---:|---------|------|
| A | @ | 服务器公网 IPv4 | 主域名解析 |
| A | * | 服务器公网 IPv4 | 泛解析（推荐，所有子域名自动生效） |
| AAAA | * | 服务器 IPv6 | IPv6 泛解析（可选） |

**Cloudflare Dashboard**：选择域名 → DNS → Records → **Add record**：

| 类型 | 名称 | 内容 | 代理状态 |
|------|:---:|---------|---------|
| A | * | 服务器 IPv4 | DNS only（灰云） |
| AAAA | * | 服务器 IPv6 | DNS only（灰云） |

> **提示**：泛解析（`*`）可一次性覆盖所有子域名，新安装的服务无需再手动添加。DNS 修改后通常 10 分钟内生效，可用 `dig 子域名.你的域名` 或在线工具 dnschecker.org 验证。

## 附录 B：SSL 证书与端口说明

### B.1 证书来源

| 访问方式 | 证书来源 | 说明 |
|---------|---------|------|
| Cloudflare Tunnel | Cloudflare 边缘自动签发 | 无需任何配置 |
| 域名反代 / 智能混合路由 | Let's Encrypt（ACME 模块自动申请） | 需 DNS 凭证用于验证 |
| IPv6 直连 | 无 | 直接 HTTP 访问 |

### B.2 HTTPS 端口选择

| 端口 | 适用场景 | 说明 |
|------|---------|------|
| 443 | 有公网 IPv4 且运营商未封锁 | 标准 HTTPS 端口，访问无需输入端口号 |
| **8443（默认）** | 国内家庭宽带/云服务器 | 运营商普遍不封锁，兼容性好 |
| 8442 / 9443 | 8443 被占用时 | 自定义高位端口 |

### B.3 修改端口后的注意事项

1. 修改端口后系统自动重启 Nginx 容器（**必须重启才能绑定新端口**）
2. 检查云服务器安全组/防火墙是否放行新端口
3. 检查路由器端口转发规则是否同步更新
4. 域名反代的服务访问需带新端口号；「Tunnel 中转服务」卡片中的访问地址会自动更新为新端口

## 附录 C：术语表

| 术语 | 说明 |
|------|------|
| 域名反代 | 流量经 DNS 解析直达服务器，由 Nginx 反代到服务，访问带 HTTPS 端口 |
| Tunnel 中转 | 流量经 Cloudflare 边缘通过隧道转发，访问免端口 |
| 智能混合路由 | 两种路由方式并存，按服务粒度选择 |
| API Token | Cloudflare 用于调用 API 的凭证，`cfut_` 开头，可配置权限 |
| Tunnel Token | cloudflared 运行时的隧道凭证，`eyJ` 开头，自动生成 |
| A 记录 | 域名 → IPv4 地址的解析记录 |
| AAAA 记录 | 域名 → IPv6 地址的解析记录 |
| CNAME 记录 | 域名 → 其他域名的别名记录（Tunnel 服务使用） |
| 泛解析（*） | 匹配所有子域名的通配记录 |
| DDNS | 动态 DNS，IP 变化时自动更新解析记录 |
