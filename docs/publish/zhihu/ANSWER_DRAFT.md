# 在 WSL 里跑一套开源自建家庭服务器，是什么体验？

**先说结论：像在自己电脑里装修了一套房子。墙是 Windows，房子是 WSL，装修队是 Docker，装修全程实测 31 分钟，事后每一面墙我都敲过一遍——13 个服务模块逐个装、逐个测、逐个记，有惊喜也有翻车，但都翻得明明白白。**

以下是我最近一次完整实测的记录。环境：Windows 上的 WSL2 + Ubuntu 24.04，对象是开源项目 EasyServer（MIT）——一个个人服务器一站式部署方案，模块化架构 + Web 管理面板 + 应用商店，内置 13 个服务模块（Nextcloud 云盘、Jellyfin 影音库、Frigate AI 监控、Joplin 笔记同步、Uptime Kuma 监控、Nginx 反代、Cloudflare Tunnel 内网穿透等）。技术栈 Python 3.11 + FastAPI + Vue 3，全部容器化。

---

**为什么是 WSL？**

因为我这台机器平时要干别的事，不想装双系统，也暂时不想再开一台云服务器交月费。WSL2 的好处是 Linux 环境完整、文件互访方便、随时 `wsl.exe --shutdown` 回到干净状态。代价是它跟原生 Linux 有些微妙差异，后面有几个坑全是栽在这些差异上的。

**第一步：装 Docker，先吃两个网络亏。**

- 第一个亏：`apt-get update` 访问 download.docker.com 一直 TLS 握手失败。盯着报错看了半天，发现解析到了 IPv6 地址，而 apt 走的 IPv6 链路不通（curl 直连反而正常）。解法朴素得感人：所有 apt 命令统一加 `-o Acquire::ForceIPv4=true`。
- 第二个亏：`docker pull` 直接超时，registry 被 DNS 污染，重试无效。解法是给 `/etc/docker/daemon.json` 配镜像加速。配完顺手记了一个数：**实测限速 25-40 KB/s**——这个数字后来反复出现，贯穿了我一整天的体验。

还有个小差异值得记住：WSL2 默认没有 systemd，Docker 服务要用 `sudo service docker start` 起，而且**每次 WSL 重启后都要来一遍**，直到你在 `/etc/wsl.conf` 里开启 systemd。

**第二步：构建，31 分钟。**

`docker compose build` 是多阶段构建：Python 3.11-slim 出后端，node:20-alpine 编译前端。首次构建实测总耗时约 **31 分钟**，其中 29.6 分钟全花在拉 node 基础层上——就是那个 25-40 KB/s 的限速。中途还断过一次（构建内 apt 连接被重置，exit 100），一度以为要重来，结果**直接重新执行就续上了**：已拉取的层命中缓存，重试成本极低。这个"先重试再说"的经验后来帮我省了不止一次。

最终产物是一个自包含镜像，**约 538 MB**，代码、前端、13 个模块的 compose 模板全在镜像里，宿主机只挂数据目录。这个设计我是喜欢的：核心引擎轻，数据跟引擎分离。

**第三步：.env，一个"文档没写透"的必做步骤。**

手动安装方式下，宿主机的 `.env` **不会**被自动创建，而 compose 声明了 `env_file: .env`，缺它 `docker compose up -d` 直接失败。复制模板只是及格线，真正的坑有两个：

- `.env.example` 默认的 `DATA_DIR=/data`、`PROJECT_ROOT=/easyserver_data` 是**容器内路径**，但这俩变量同时被用作**宿主机卷挂载源**——不改的话，数据目录会被挂到系统根目录去。我改成了真实用户路径。
- 不预设 `JWT_SECRET` 的话，容器每次重启都重新生成密钥，所有登录状态作废。一行 `openssl rand -hex 32` 的事，但不做很烦。

**第四步：启动与初始化，比预期利索。**

`docker compose up -d` 之后，entrypoint 自动完成初始化（建网络、铺模块模板），容器健康检查通过变 `Up (healthy)`。浏览器打开 `localhost:8900`，一个极简向导：填域名、填 SSL 邮箱、设管理员密码——就三步，而且系统**没有用户名概念也没有默认密码**，单管理员密码认证，Token 实测有效期约 7 天。面板是 Vue 3 + Element Plus 的，应用商店按需装服务，默认一个模块都不装，干净。

**重头戏：13 个模块逐个装、逐个测。**

这才是"体验"二字最浓的部分。我把每个模块都走了 install → status → 健康验证 → logs → stop → uninstall 六个阶段，下面挑有故事的讲。

**先说三个惊喜：**

- **Uptime Kuma（服务监控）**：13 个模块里唯一一个六阶段一次通过、全程零人工干预的。镜像本地命中后安装实测 **5 秒**完成，容器自带 healthcheck，直接 healthy。
- **Frigate（AI 视频监控）**：7.48 GB 的大家伙，但镜像来自 ghcr.io，直连健康、不经 Docker Hub 那条限速链路，拉取反而顺畅。而且**没有摄像头也完全可用**——UI 和 API 照常工作，容错设计不错，可以先装后配。
- **Nextcloud（私有云盘）**：首次初始化实测**约 40 秒**完成（比文档预期的 1-3 分钟快不少），装完 `status.php` 一查，34.0.3 版本、installed=true，直接能登录。

![占位：模块应用商店](IMAGE_PLACEHOLDER-module-store)

**再说三个翻车（都有解）：**

- **Jellyfin 在 WSL2 上默认配置起不来**。默认 host 网络模式下，容器以 SIGSEGV(139) 崩溃循环，`Restarting (139)` 刷屏。排查后确认是 WSL2 mirrored 网络下 .NET 的 host 网络兼容性问题，换 bridge 模式对照实验，容器稳定运行，日志 `Startup complete 0:00:17`——**17 秒启动**。教训：WSL2 用户装 Jellyfin 记得选 bridge。
- **"单文件挂载陷阱"**。ddns-go 的配置文件在 compose 里按单文件方式挂载，但引擎不预创建这个宿主文件，Docker 发现源不存在时会自动创建一个**同名目录**而不是文件。于是容器活着、界面正常，但配置永远保存不了，日志里一句 `is a directory` 道破天机。这个陷阱在另一个模块（NoteDiscovery）上又复现了一例。解法是安装前手动 `touch` 出真文件。
- **build 型模块的面板安装走不通**。Nextcloud、备份这类需要本地构建镜像的模块，走面板安装会在拉镜像阶段结构性失败（引擎对含 `build:` 的服务仍逐镜像去 registry 拉）。降级路径是手动 `docker compose build && up`，实测都能跑通——Nextcloud 构建约 5 分钟，备份模块构建约 40 秒，restic 备份引擎初始化、全量备份、保留策略全部正常。

还有个贯穿全程的环境特性值得单说：**WSL2 mirrored 模式下，Windows 侧进程占用的端口，在 WSL 里用 `ss`、`lsof` 根本查不到**。我好几次对着"绑定失败但查无占用"怀疑人生，最后都得靠 Windows 侧的 `netstat.exe` 找到真凶（某 IDE 的端口监听）。所以实测里一串端口都被迫改了号：8081→18081、8888→18888、5000→15000……形成了独特的"18 段"风景线。

---

**数字盘点**（全部实测）：

- 核心引擎镜像：约 **538 MB**
- 首次构建：**约 31 分钟**（node 基础层 29.6 分钟，受 mirror 限速 25-40 KB/s 拖累；大镜像拉取超时约 600s 量级，所以后来学乖了，先 `docker pull` 预热再安装）
- 13 个模块六阶段测试：1 个全流程一次通过（Uptime Kuma），5 个通过（其中 4 个需人工修复或为无凭据降级断言），7 个存在已确认的行为差异或缺陷记录在案（host 崩溃、单文件陷阱、安装状态残留等）
- Nextcloud 首次初始化：**约 40 秒**
- Uptime Kuma 安装：**约 5 秒**；ddns-go 安装：**3.3 秒**（预拉取生效）；Jellyfin bridge 启动：**17 秒**

**体验总结：**

它像装修房子。图纸（README 和文档）是齐的，水电（网络五种模式：域名反代 / IPv6 直连 / Cloudflare Tunnel / 混合路由 / 自由配置）是通到户的，硬装（核心引擎）一次成型。但软装环节，13 件家具里有几件说明书和实物有出入——好在每一处出入我都拍了照、记了档，哪些能直接用、哪些要先垫块木头，都写得清清楚楚。

值得试吗？如果你想在手头这台电脑上低成本试水"自建全家桶"，WSL2 + 这套东西的组合几乎是零硬件成本的起点：面板可视化、模块即装即卸、数据目录独立。如果非要挑刺：镜像拉取速度是环境问题不是项目问题，但模块层面确实还有几个实测确认的缺陷待上游修复——这也是我把实测记录完整留下的原因，脚注里都标了缺陷编号，不吹不黑。
